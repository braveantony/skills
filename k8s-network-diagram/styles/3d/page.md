# 網頁：架構與現行設定

`styles/3d/assets/index.html` 是現行版本。這份文件說明它的結構和每個參數的用意。改參數之前先讀對應的段落：這些數值大多是審閱或實測後才定下來的。

## 版面

```
header（標題、3D／平面圖切換）
grid
├─ .stage（直欄）
│   ├─ .bar     圖例（連線 ①②）＋ 按鈕（回到全圖、全螢幕）
│   ├─ #vp      3D 畫面：canvas、#labels（標籤、引線 svg）
│   └─ .cap     步驟說明列（只在全螢幕顯示）：‹ 編號 說明 › 播放
├─ .note        操作提示
├─ #parts       「圖上的元件」清單（只在 3D 畫面寬度 < 640px 時顯示）
└─ aside        步驟 1–7、上一步／播放全部／下一步、頁尾兩行註解
```

- **3D 畫面上不疊任何控制項。** 圖例、按鈕、說明列都在 `#vp` 外面，所以不會蓋到圖案。
- `#vp` 寬度 < 640px 時，`.stage` 加上 `compact`（手機模式）：字縮小、工具列變矮、`podman2` 的網段換到第二行。
- 淺色主題，色彩都定義成 `:root` token：
  - 連線 ①：`--c1 #8e1f8c`
  - 連線 ②：`--c2-fill #4cb85a`
  - 會變動的值的灰底：`--chip #e2e3e6`
- 字型：Noto Sans TC（內文）、JetBrains Mono（IP、網卡名稱）。

## 3D 場景

- three.js 0.147.0（jsDelivr，附 SRI），`OrthographicCamera`。
- 視角：
  - 起始方向是 `D.camdir`、目標點是 `D.target`；
  - `minZoom 0.4`、`maxZoom 5`，鏡頭最低仰角是 `maxPolarAngle 0.47π`；
  - 拖曳慣性 `dampingFactor 0.12`。
- `fit()` 設定可視範圍：
  - 半寬 `hw = 寬高比 >= 1.5 ? 27 : max(20 × 寬高比, 22)`（世界單位）；
  - 畫面尺寸改變時，用 `ResizeObserver` 重新計算。
- 模型外框：每個網格加 `EdgesGeometry(35°)`，顏色 `#15171c`、不透明度 0.55。
- **container 改色**：載入模型時，依材質名稱覆寫顏色。
  - `container` → `#e6a23c`
  - `container_top` → `#a86a14`
  - 兩者都要先 `convertSRGBToLinear()`，否則顏色會偏淡。
- **封包**：
  - 本體是半徑 0.42 的球，外加半徑 0.75、不透明度 0.25 的光暈；
  - 速度：每秒 9 個世界單位，一段至少 1.2 秒；
  - 手動點選的步驟：到終點停 0.6 秒後重跑；
  - 自動播放（`hold`）：到終點就停住；
  - 單點的步驟（4、7）：只有光暈脈動。

## 資料區（換環境時要改的地方）

| 名稱 | 內容 |
|---|---|
| `D.anchors` | 模型上的錨點（網卡中心、Pod 頂部、主機前緣等），由 Blender 腳本匯出 |
| `D.p1`、`D.p2` | 連線 ①、② 的折線頂點 |
| `D.target`、`D.camdir` | 預設注視點、預設鏡頭方向 |
| `STEPS[]` | `c`（屬於哪條連線）、`t`／`s`（兩行文字，和平面圖逐字相同）、`at`（這一步講的點）、`seg`（封包走的區段，`[路徑, 起點索引, 終點索引]`；ARP 這類不是連線封包的步驟設 `null`）、`rel`（這一步相關的標籤） |
| `ANCH` | 標籤名稱 → 錨點 |
| `label(...)` | 每個標籤的 HTML。會變動的值包在 `<span class="v">` 裡 |
| `BOXES`、`CABLES`、`NODES`（→ `heavyBoxes`、`heavySegs`、`lightSegs`，也設成 `window.OBST`） | 文字要避開的線段和方塊（世界座標），見下方「自動擺放」 |
| `#parts` | 手機的元件清單，內容要和標籤一致 |

總覽的取景點、Pod 的取景範圍、連線膠囊的高度都從 `NODES`、`BOXES`、`D.p1`／`D.p2` 算，沒有另外寫死的座標。

### 資料區以外寫死的地方

換環境時這些也要一起改。量測抓得到的只有兩種：`ANCHOR_ON` 沒改，`model` 會判 FAIL；`LABEL_BOX` 指向不存在的鍵或 `BOXES` 名稱，頁面載入時的資料檢查會丟錯，結果是 `RESULT ERROR`。其餘（`<title>`、eyebrow、`<h1>`、`#note`、圖例、alt、頁尾、`prio()`）量測不檢查，要看截圖。

| 位置 | 內容 | 什麼時候要改 |
|---|---|---|
| `<title>` | 分頁標題（瀏覽器分頁、Artifact 清單上的名稱），例如「看板連線 3D」 | 每次 |
| 頁首 `.eyebrow`、`<h1>` | `.eyebrow` 用 spec 的 `eyebrow`，沒有時只寫「<叢集> 實測」，不要留範例的課程名稱。`<h1>` 只放 `title` 冒號前的部分（例如「看板連線怎麼走」），`<h1>` 裡的 `<small>` 放 spec 的 `subtitle`（沒有時用 `title` 冒號後的部分）；完整 title 放進 `<h1>` 在手機上會在詞中間斷行 | 每次 |
| `#note` | 操作提示「拖曳旋轉 · 滾輪或雙指縮放 · 點圓圈或步驟清單看每一步」 | 互動方式改變時 |
| `.legend` | 「連線 ①：主機 ↔ Envoy」「連線 ②：Envoy ↔ Pod」 | 連線兩端不同時 |
| 平面圖分頁的 `<img alt>` | 平面圖的文字描述 | 每次 |
| 頁尾 `.foot` | 灰底註解、實測日期與叢集 | 每次（灰底註解依 `references/principles.md` 第 4 條） |
| `LABEL_BOX` | 標籤鍵 → `BOXES` 名稱：標籤是 Pod 名稱時，把整個 Pod 框入鏡（座標從 `BOXES` 讀） | Pod、鍵名或 `BOXES` 名稱改變時 |
| `ANCHOR_ON` | 錨點 → 它該落在的 `BOXES`／`NODES` 名稱、`p1`／`p2`，或 `mesh:<網格名稱>`（結尾 `*` 表示前綴），量測用 | 錨點或名稱改變時 |
| `prio()` 的 `it.key === "envoy" \|\| it.key === "koupa"` | Pod 名稱的優先順序 | 鍵名改變時 |
| `scripts/overlap.mjs` 的 `p1`／`p2` | 量測寫死兩條連線（障礙物、交叉計數、模型比對） | 連線不是兩條時（見下一段） |

`scripts/overlap.mjs` 在連線是兩條（`p1`、`p2`）時不用改，也不要為了某個環境去改 skill 裡的這份。連線數不同時，把它複製到工作資料夾改好，再照 `run-overlap.sh` 的做法執行；網格前綴（`path`、`Cone`、`Sphere`、`cab`、`veth`、`node_`）不同時也一樣。拓撲相同時，它從頁面讀障礙物（`window.OBST`）、步驟數（`STEPS.length`）、相關標籤（`STEPS[].rel` 與標籤的 `data-key`），手機橫放測的是封包路徑段數最多的那一步。

## 自動擺放（`layout()`）

標籤、步驟圓圈、連線膠囊都是 DOM 方塊，每次相機變動就在螢幕座標重新擺放。

- **候選位置**：從錨點往 16 個方向，在 8、20、36、56、80、110、150、200、260、330px 這些距離試放。
- **碰撞成本**（成本 ≥ 1 就算「不乾淨」，這種位置**永遠不選**）：

  | 碰到什麼 | 成本 |
  |---|---|
  | 連線、實體網路線（含 lxc 到 Pod 的 veth），往外 4px | 10 |
  | 目前這一步的封包路徑，往外 `halo` px（光暈最大半徑 + 4） | 10 |
  | 網卡、交換器、主機、兩個 Pod（投影後的外接矩形） | 10 |
  | 已經放好的文字 | 50 |
  | 已經畫好的引線 | 10 |
  | 節點外框線 | 1（也算不乾淨） |
  | 被畫面邊緣切到 | 不能放 |
  | 引線穿過其他文字 | 15 |
  | 引線穿過不屬於自己的模型 | 8 |

  「屬於自己的模型」：錨點落在該模型投影外接矩形的 ±14px 內。
- **排序分數**（只在乾淨的位置之間比較）：
  - 距離 × `dk`（圓圈 0.03、其他 0.012）；
  - 引線跨過連線每次 +0.8，和其他引線交叉每次 +1.2（不會讓位置變不乾淨）；
  - 和偏好方向的差距 × 0.05。
- **優先順序**（數字越小越先放，9 是不顯示）：

  | 元素 | 總覽 | 步驟中 |
  |---|---|---|
  | 目前步驟的圓圈 | — | 0 |
  | 目前步驟的相關標籤（`rel`） | — | 1 |
  | 其他標籤 | 桌面 1（必須出現）；手機：節點名稱 2、其他 3 | 節點、Pod 名稱 2；其他：桌面 3、手機 9 |
  | 目前連線的膠囊 | — | 1.6 |
  | 其他膠囊 | 2 | 2 |
  | 步驟圓圈 | 2 | 其他步驟 9 |

- **找不到乾淨位置**：一律隱藏。優先順序 < 1.5 的元素（必要元素）放不下時，會觸發鏡頭拉遠（見「取景」）。
- **距離上限**：
  - 膠囊只能貼在自己的線旁 36px 內；如果是目前這一步的連線，放寬到光暈之外 40px；
  - 優先順序 ≥ 2 的元素，以及總覽時的圓圈，最遠 110px；
  - 必要元素沒有上限。
- **防跳動**：舊位置仍然乾淨，而且分數只比最佳差 0.3 以內，就保留舊位置。換步驟、回到全圖、畫面尺寸改變時，呼叫 `relayout(true)` 清掉舊位置。
- **效能**：元素尺寸只在 `relayout()` 後重量一次；引線 SVG 沒變就不重寫；相機矩陣、zoom、畫面尺寸、目前步驟都沒變就不重排。
- **引線**：灰色 `#8a8d96`、1.2px、虛線 `3 2`，錨點畫一個小圓點。距離超過 12px 才畫；膠囊不畫引線。

## 取景（`frameStep(st)`、`frameOverview()`）

- **步驟**：
  - 要入鏡的點：這一步的路徑點、`at`、`rel` 的錨點；`rel` 有 Pod 名稱時，整個 Pod 也要入鏡。
  - 四周留白：桌面 170×90px、手機 70×60px。
  - zoom 上限 1.8、下限 `minZoom`。
- **先試排再移動**：
  - 程式在背景把鏡頭放到目標位置，跑一次 `layout(true)`。這是乾跑，不會改到畫面。
  - 必要元素放不下就先試排、zoom × 0.9 再試：步驟最多 4 次，總覽最多 10 次。
  - 使用者轉動視角後還是放不下時，`checkMust()` 每次 × 0.85，最多 3 次。
  - 算好之後才跑一段 0.7 秒、ease-out 的鏡頭動畫。這樣換步驟時圓圈不會消失。
- **`checkMust()`**：使用者旋轉之後，如果必要元素放不下，最多再拉遠 3 次。使用者自己操作過鏡頭（`userMoved`）就不再拉遠，到達 `minZoom` 也停止。
- **總覽**：
  - 要入鏡的範圍：兩個節點、交換器、主機；四周留白：桌面 60×40px、手機 16px。
  - 桌面：所有標籤都必須放得下。原本的角度放不下時，依序試繞垂直軸 ±30°、±60°、±90°、±120°，取「全部放得下而且 zoom 最大」的角度。
  - 手機：固定原本的角度，完整資訊交給 `#parts` 清單。
- **畫面尺寸改變**（`fit()`）：清掉舊位置。使用者沒調過視角就重新取景，並從頭計算要不要拉遠；調過就只重排文字。
- `focusTo()`：目標和目前位置相同，或和進行中的動畫相同，就不重新起動畫。

## 播放與控制

- `go(i)`：更新步驟清單、說明列和 `aria-live`，接著起封包動畫、取景，最後 `relayout(true)`。
- **播放全部**：每一步停留 `max(3200, 封包時間 + 1400)` ms；減少動態效果時固定 4000ms。
- **回到全圖**：清掉目前步驟、停止播放、封包消失，回到總覽視角；暫時關掉慣性再 `controls.update()`，消除拖曳殘留的動量。
- **全螢幕**：
  - 優先用 `requestFullscreen()`；失敗就加上 `.stage.max`（fixed、蓋滿視窗）。
  - Esc 可以結束 `.max`。
  - 切換後只呼叫一次 `fitStage()`，由 `fit()` 負責重新取景。
- **減少動態效果**：`focusTo` 直接跳到定位、`enableDamping` 關閉、封包不動。偏好設定中途改變時，用 `onReduce()` 同步。
- **無障礙**：
  - canvas 可以聚焦，方向鍵可以平移；
  - 步驟圓圈的 `aria-label` 包含步驟文字；
  - `#live` 用 `aria-live` 唸出目前步驟。

## 發布成 Artifact

- 發布的檔案：`index.html`（不要寫 doctype、html、head、body，平台會自動包上）、`scene-glb.txt`、`final.png`（平面圖分頁用的圖）。
- 更新時，用同一個 `url` 重新發布 `index.html`。沒有一起傳的其他檔案會保留。
- `.glb` 不是可以發布的檔案類型，所以網頁用 `fetch("scene-glb.txt")` → `atob` → `GLTFLoader().parse()` 載入模型。
